# Схемы

## 1. Сначала — готовые макеты

В шаблоне уже есть схемы из компонентов. Они стабильнее нарисованных агентом и правятся
свойствами, поэтому всегда начинать с них (подробности — `slides-template/references/layouts.md`):

| Что показать | Макет |
|---|---|
| Две стороны, было/стало, мы/конкурент | `m-before-after`, `m-list-2` |
| Три варианта или шага, один главный | `m-cards-3` (акцент на главной карточке), `m-process-4` с тремя шагами |
| Процесс из 2–4 шагов с текущим этапом | `m-process-4` (акцент — `State: Accent` у шага) |
| Поток с возвратом, «ходим по кругу» | `m-flow-loop` |
| Центр и составляющие | `m-hierarchy` |
| План по кварталам | `m-roadmap` |
| Как устроено и что дало | `m-system-numbers` |
| До 6 пунктов последовательности | `m-list-numbered` |

Число карточек и шагов меняется скриптом C (`count`); пустые блоки не оставлять.

## 2. Если макета нет — нарисовать

Скрипт `references/diagram-script.md` рисует на холсте `canvas` макета `m-canvas` (подготовка —
скрипты A и E из `slides-figma-build`):
- `flow` — 2–6 этапов слева направо со стрелками. У узла может быть `callout` — жёлтая плашка с
  цитатой или правилом (так авторы оформили «Замечания – в правила!»). `LOOP: { from, to, label }`
  рисует обратную стрелку под карточками для истории «ходим по кругу» (`job` *увидеть застревание*);
- `matrix` — 2×2 с подписями осей;
- `hub` — центр и 3–6 связанных блоков;
- `system-numbers` — сверху 2–4 карточки механизма, снизу 2–3 крупных числа (`NUMBERS`). Для темы,
  где спикер рассказывает и как устроено, и чего достигли: так автор слил два слайда Work OS в один.

Текст узлов: `title` 1–3 слова, `text` до 60 символов, `callout` до 50. Акцент (`ACCENT`) — один
узел, который несёт вывод заголовка; в `system-numbers` — главная связка механизма. Цвета карточек
и стрелок привязаны к переменным `Manila Slides`. `flow` с плашкой и возвратом проверен на
шаблоне «Манила 30».

После рисования — один скриншот. Типичные дефекты: текст не влез в карточку (сократить),
стрелка упирается в карточку (уменьшить число узлов).

## 3. Сложные схемы

Оргструктуры, архитектура систем, BPMN с ветвлениями не рисовать на слайде. Предложить
пользователю один из вариантов: упростить до 4–6 блоков под `flow`/`hub`; собрать черновик в
FigJam инструментом `generate_diagram` (Mermaid) и перенести вручную; вынести схему в приложение.
