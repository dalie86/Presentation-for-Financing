# Обучение на правках авторов

Модель не дообучается на весах: 20–50 пар слишком мало, а стиль команды меняется быстрее, чем
имеет смысл переобучать. «Обучение» здесь — тот же цикл, что у Refine-agent в Atomic:
**правка человека → правило в навыке → следующая колода без этой правки**. Работает за счёт
инструкций и примеров, которые модель читает при каждой сборке, и измеряется числом правок.

Накопленный каталог — `references/edit-patterns.md`. Читать его перед сборкой любой колоды
(навыки `slides-text-fit`, `slides-visual-story`, `slides-qa` уже ссылаются на него).

## Цикл

### 1. Собрать пары

Источник пар — одно из двух:
- **Раздел, собранный плагином, и его финальная версия.** Перед показом автор дублирует раздел или
  присылает ссылку на финальный файл. Сгенерированную версию берём по `build-log.json`.
- **Фрейм-сравнение,** как в файле «Обучение модели»: слева сгенерировано, справа финал, пары на
  одной высоте.

Снять тексты скриптом из `references/capture-script.md` (только чтение) и скриншоты пар —
скриншоты нужны для правок вёрстки, которые по тексту не видны. Сохранить ответ скрипта в рабочую
папку `pairs.json`.

### 2. Посчитать правки

Кодом (Python, `difflib`) по каждой паре:
- **доля изменённого текста** — 1 − `SequenceMatcher(None, gen, final).ratio()` по склеенному тексту;
- **объём** — символов было / стало;
- **заголовок** — изменён ли, длина было / стало;
- **механические правки** — точки в конце строк, «ё», дефис вместо тире, строчная буква в начале
  подписи.

```python
import json, difflib, re
pairs = json.load(open('pairs.json'))['pairs']
def body(lines): return [l.split('|', 2)[2] for l in (lines or [])]
rows = []
for p in pairs:
    g, f = body(p['g']), body(p['f'])
    if not f: rows.append((p['gen'], 'удалён или слит', None, None)); continue
    gs, fs = ' '.join(g), ' '.join(f)
    changed = 1 - difflib.SequenceMatcher(None, gs, fs).ratio()
    rows.append((p['gen'], round(changed * 100), len(gs), len(fs)))
accepted = sum(1 for r in rows if isinstance(r[1], int) and r[1] < 5)
mech = {k: sum(len(re.findall(rx, ' '.join(body(p['g'])))) for p in pairs) for k, rx in
        {'точки': r'[^.]\.(?= |$)', 'дефис': r' - ', 'ё': 'ё'}.items()}
print(f'принято без правок текста: {accepted} из {len(rows)}'); print(mech)
for r in rows: print(r)
```

Слайд считается **принятым без правок текста**, если доля изменённого текста < 5 % и заголовок не
менялся. Это главная метрика — аналог PASS@1: доля слайдов, принятых с первой попытки.

### 3. Отделить ремесло от содержания

Для каждой правки решить класс:
- **ремесло** — тот же факт сказан иначе, сокращён, переставлен, выделен; изменена раскладка;
- **содержание** — появилась цифра, имя, термин или факт, которого не было в исходном материале
  (сверить с исходником колоды: сторилайн, текст выступления, данные);
- **вкус** — решение, встречающееся у одного автора и противоречащее другому (например, «ё»).

Если исходника нет, а правка похожа на новый факт — считать содержанием. Спорные случаи вынести
автору одним списком: «это ваше уточнение или стиль, которому нам следовать всегда?».

### 4. Вывести правила

Правило записывается в `references/edit-patterns.md`, только если:
- встретилось **не меньше чем в двух парах** или у двух авторов (одиночный случай — в раздел
  «наблюдения», не в правило);
- его можно проверить по готовому слайду (иначе модель не поймёт, выполнено ли оно);
- оно не противоречит другому правилу; если противоречит — уточнить старое, а не добавлять второе.

Каждое правило: формулировка, класс, сила (в скольких парах из подходящих), пример «было → стало».
Механические правила (точки, тире, регистр) дополнительно добавить в автоматическую проверку
`slides-qa`, чтобы модель ловила их сама.

### 5. Применить

Изменения в навыках — одним предложением правок, которое человек смотрит до сохранения:
- текстовые правила → `slides-text-fit`;
- заголовки → `slides-storyline`;
- вёрстка и образ → `slides-visual-story` (раздел «Частые расхождения») и `slides-template`;
- новые проверки → скрипт `slides-qa`.

Затем пересобрать пакет плагина и поднять версию.

### 6. Измерить

На следующей колоде повторить шаги 1–2 и сравнить метрику с базовой линией из
`references/edit-patterns.md` (раздел 5). Если доля принятых слайдов не выросла — правило не
работает: переформулировать конкретнее или добавить пример.

## Чего не делать

- Не учить на содержании: новые цифры автора — не ошибка модели. Вместо этого в брифе спрашивать
  дату актуальности цифр и принятые в команде термины.
- Не превращать вкус одного автора в общее правило без подтверждения.
- Не переписывать навыки без показа правок человеку.
