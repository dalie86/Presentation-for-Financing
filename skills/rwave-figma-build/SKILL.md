# Сборка колоды в Figma Slides

Работать только через официальный удалённый Figma MCP (`use_figma`). Готовые проверенные скрипты
лежат в `references/scripts.md` — копировать их дословно, меняя только блок `// INPUT`.

## Перед первым вызовом

1. Загрузить навыки Figma `figma-use` и `figma-use-slides` (через плагин Figma или ресурсы
   `skill://figma/figma-use/SKILL.md`, `skill://figma/figma-use-slides/SKILL.md`). Это обязательное
   требование сервера; без них `use_figma` чаще ломается.
2. Взять fileKey из ссылки пользователя (`figma.com/slides/<fileKey>/...`). По умолчанию — шаблон
   `KONBkbQA2HJsahHuiJBl7p`.
3. Вызвать `create_session` с fileKey и коротким описанием задачи; дальше передавать полученный
   `sessionId` в каждый вызов.
4. Если `whoami` или первый вызов падает с ошибкой прав — сказать пользователю, что нужен доступ
   на редактирование файла и место Full в платном плане Figma, и остановиться.

## Порядок сборки

Работать партиями по 4–6 слайдов. Для каждой партии строго три вызова:

1. **A — клонирование.** Первая партия создаёт раздел (`SECTION_NAME` = «<название колоды> —
   черновик»), следующие дописывают в него (`ROW_ID`). Записать `rowId` и id слайдов.
2. **B — разметка и инвентарь.** Отдельным вызовом: только после клонирования становятся доступны
   поля внутри шапки. Ответ — список слотов с подсказками и вместимостью.
3. **C — заполнение.** Сопоставить текст из slide-spec со слотами по подсказкам из инвентаря,
   а не по догадке о порядке. Проверить ответ: если `lines` больше допустимого — сократить текст
   и перезаписать слот.

Слайды под графики и схемы: клонировать `content-canvas` в той же партии (A), затем вместо B/C
вызвать скрипт E и рисовать скриптом из `rwave-charts` или `rwave-diagrams`.

Заметки докладчика (скрипт D) добавлять, только если пользователь просил текст выступления или
«колоду, готовую к показу», либо есть `visual-map.md`. Заметки — фразы `say` в порядке якорей с
пометкой «→ показать на <элемент>».

Акцент (жёлтый) ставить на элемент `accent` из `slide-spec.md`: выбрать вариант макета с акцентом на
нужном месте (например, `process-4` с акцентом на 2-м шаге), а в схемах и графиках — передать индекс
в `ACCENT` / `HIGHLIGHT`. Если подходящего варианта макета нет — оставить как есть и сообщить.

Вести журнал сборки в файле `build-log.json` рабочей папки: fileKey, sessionId, rowId, для
каждого слайда — номер в плане, ключ макета, id клона и инвентарь слотов. Журнал нужен для
правок и для проверяющего.

## Правила

- Никогда не изменять исходные макеты шаблона и чужие разделы. Все правки — только в разделе,
  созданном в этой сессии (или в разделе, на который явно указал пользователь).
- Не удалять слайды, кроме своих черновых и только по просьбе пользователя (скрипт F).
- Не менять цвета, шрифты, размеры и позиции элементов макета. Меняется только текст.
- Текст для слайдов уже должен быть сжат (`rwave-text-fit`). Сборка не место для редактуры:
  если текст не влез, вернуть слот на сокращение по тем же правилам.
- При ошибке `use_figma` с `safeToRetryWithoutCanvasRead: false` сначала прочитать раздел
  (`row.children` и имена слотов), понять, что успело примениться, и только потом повторять.
- Лимит Figma MCP — около 200 вызовов в день на платном месте. Колода на 15–20 слайдов занимает
  ~25–40 вызовов вместе со скриншотами; не тратить вызовы на лишние скриншоты. Заметки докладчика
  ставить раньше финальных скриншотов, чтобы лимит не кончился на них. Если лимит исчерпан — отдать
  заметки пользователю файлом.
- Скрипт A может склонировать всю колоду за один вызов. Если пользователь назвал существующий
  раздел — писать в него через `ROW_ID`.
- Скриншоты: `get_screenshot` возвращает ссылку на www.figma.com, которая из рабочей среды может
  быть недоступна; тогда передавать `enableBase64Response: true` и `maxDimension` 640–700.
- Картинки: `upload_assets` требует POST на mcp.figma.com, который из рабочей среды может быть
  закрыт; `figma.createImage(figma.base64Decode(...))` работает, но base64 в коде очень дорог по
  объёму. Для мемов и фото ставить подписанную рамку-заглушку и отдавать картинку файлом.
