# Шаблон «Манила 30»

Файл шаблона: `https://www.figma.com/slides/Va5dPaSmSmwC228TKjiaGE`. Для каждой колоды
пользователь делает копию файла и даёт ссылку на неё; без ссылки колода собирается новым
разделом в самом шаблоне.

Шаблон — источник истины для стиля. Агент не рисует слайды с нуля: он клонирует готовые макеты и
меняет в них только текст — через свойства компонентов. Рисовать самому разрешено только графики
и нестандартные схемы, и только во фрейме `canvas` макетов `m-canvas` / `m-canvas-desc`
(навыки `slides-charts`, `slides-diagrams`). Цвета — только переменными коллекции `Manila Slides`.

## Справочник

`references/layouts.md` — токены, компоненты и их свойства, 35 макетов с id и вместимостью,
правила стиля. Читать при каждом подборе макетов и перед рисованием.

## Как выбирать макет

0. Если есть `visual-map.md` (навык `slides-visual-story`) — форма уже выбрана по `job`; здесь
   только уточнить конкретный макет и акцент. Иначе — шаг 1.
1. Определить тип сообщения слайда, а не его тему:
   - изменение для клиента (проблема → решение → метрика) → `m-value`, без иллюстрации `m-value-3col`;
   - сравнение двух сторон, было/стало → `m-before-after`, `m-list-2`;
   - перечень равноправных пунктов: 3 → `m-cards-3`, 4 → `m-cards-2x2` / `m-cards-4-rows`, 6 → `m-cards-6`;
   - последовательность шагов: до 4 → `m-process-4` (лишний шаг удалить), 6 → `m-list-numbered`,
     цикл → `m-flow-loop`, план по времени → `m-roadmap`;
   - центр и составляющие → `m-hierarchy`;
   - одна-три цифры → `m-numbers-3`, `m-numbers-accent`; устройство и результат → `m-system-numbers`;
   - таблица → `m-table`, `m-table-chart`;
   - динамика, доли, сравнение величин → `m-bars`, `m-columns`, `m-plan-fact` или `m-canvas` + график;
   - начало новой части → `m-divider-big`, `m-divider-number`; вопрос залу → `m-divider-question`;
   - один сильный тезис со сноской → `m-thesis`;
   - термины, продукты, команды → `m-tags-cloud`.
2. Проверить, что текст влезает в вместимость полей (85 % от оценки). Не влезает — сначала
   сокращать текст (`slides-text-fit`), затем брать макет с бо́льшим числом полей или делить слайд.
3. Чередовать макеты: не больше двух одинаковых подряд.
4. Число пунктов = числу карточек. Карточки в макетах лежат в auto layout: лишние удаляются,
   недостающие дублируются скриптом C (`count`). Пустые карточки не оставлять.
5. **Подзаголовок.** Авторы почти всегда делят длинный вывод на короткий заголовок и строку под
   ним. Место для подзаголовка — шапка `Header + description` (`m-numbers-3`, `m-canvas-desc`) или
   первая строка контента; у остальных макетов вывод должен уместиться в заголовок шапки (72 px,
   1–2 строки по ~40 символов).
6. **Иллюстрация.** На слайде с малым объёмом текста — макет с иллюстрацией (`m-value`, `m-thesis`,
   титулы, перебивки, финал), если сюжет картинки не спорит со смыслом. Иначе — пометка `designer:`.
7. **Акцент.** Один жёлтый элемент: вариант `Style=Accent` / `State=Accent` у нужной карточки,
   шага, тега или числа — там, где спикер говорит «главное».

## Особенности, о которых легко забыть

- Имена слайдов в Figma Slides — номера; макеты искать по id из каталога.
- У библиотечной шапки `Header` булевы свойства `Tag 1`, `Tag 2` должны быть выключены.
- Шапка `Type=Title` (титулы, Q&A, финал) несёт «Райффайзен Банк» и логотип — её текст не менять.
- Полосы графика `Bar row` в инстансе не растягиваются: для своей длины инстанс отсоединяют.
- Картинки (мемы, фото) скриптом вставить дорого: base64 в коде, а загрузка файлов в Figma из
  рабочей среды может быть закрыта. Ставить подписанную рамку-заглушку и отдавать картинку файлом.
